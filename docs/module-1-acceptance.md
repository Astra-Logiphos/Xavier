# 模块一：本地后端与记忆激活验收

仅交付 Windows。Android 和模块二至九未在本模块实现。

## 打开与连接

1. 完整解压本次 `xinghui-windows.zip` 到固定目录，保留 exe、DLL、data、backend 和三个 bat 文件。不要覆盖旧包；先退出旧版应用和后端。
2. 双击 `start_backend.bat`。预期看到 `http://127.0.0.1:8080`、令牌文件路径和“本地后端已就绪”。包内带 Python，不用另外安装 Python 或 Flutter。窗口保持打开。
3. 双击 `xinghui_companion.exe` → 设置 → “连接本地后端”。预期顶部显示“本地已连接”，保存聊天开关开启。应用会读取同一 Windows 用户的令牌文件，不需要把令牌发给任何人。

## 聊天与记忆跨重启

1. 聊天页发送“今天想一起看星星”。预期收到回复，保存状态为 true。
2. 发送“记住这件事：我喜欢星空”。打开“记忆”页（标题“他记得的事”），预期出现“我喜欢星空”。
3. 完全退出 App，重新打开 → 聊天。预期上述两轮仍在；打开记忆页，内容仍在。
4. 关闭后端窗口后重新双击 bat，重开 App。预期聊天和记忆仍在，令牌文件不变。

## 记忆管理与隐私

1. 记忆 → 添加记忆 → 内容填写“我喜欢小鸟”，保留“同意保存” → 保存。预期列表出现新记录。
2. 编辑该记录，改为“我喜欢钓鱼” → 保存。预期刷新为新内容；重开 App 后仍是新内容。
3. 删除该记录 → 确认。预期消失，重开后也不出现。
4. 聊天勾选“本轮不保存”，发送一条测试消息。预期保存为 false，重开后该轮消失。
5. 设置关闭“保存聊天”，重启后端和 App。预期开关仍关闭，不会被启动器重新开启。
6. 人设资料、相处记忆候选仍遵循原有同意与审核机制，不自动把所有聊天转成长期记忆。规则回复能力与模型推理能力分开。

## 登录自启与自动重启

1. 保持包的目录不变，双击 `enable_backend_autostart.bat`。预期提示已启用登录自启。它仅写入当前用户启动文件夹，无需管理员权限。
2. 下次 Windows 登录后打开 App → 设置 → 连接本地后端。预期连通。关闭 App 不关闭后端。
3. 如要取消，双击 `disable_backend_autostart.bat`。预期提示已取消登录自启。
4. 测试崩溃恢复时，只结束命令行含 `-m server.api.app` 的 Python 子进程，不结束启动器。预期约 5 秒后自动重启，聊天与记忆仍在。退出监督程序本身不会自动复活它，登录自启会在下一次登录启动。
5. 若连续三次启动失败，启动器停止并提示检查日志，避免无限占用资源。

## 数据位置与故障

- 数据库：`%LOCALAPPDATA%\XinghuiCompanion\backend\xinghui.db`。
- 访问令牌：同目录 `auth_token.txt`；不要分享或提交。应用访问令牌与模型 API Key 是不同凭据。
- 启动日志：同目录 `backend.log`，不记录聊天请求正文。
- 本地后端只监听 `127.0.0.1:8080`；不开放网络服务器。
- 外观和背景保存在 App 设备存储；聊天、记忆、学习、打卡、审核数据保存在本机 SQLite。未连接时聊天仅在当前会话可见。
- 端口被占用、令牌文件损坏等会明确报错。不要删除数据库来修复连接问题。
- 数据库尚未加密，需保护自己的 Windows 账号；备份/恢复界面留待模块九。
