# 架构与演进

Flutter Windows → 本机 HTTP 回环 Bearer API → 可替换 LLMProvider / SourceConnector / STTProvider / TTSProvider。
数据库使用本机 SQLite 数据库，`records` 按 kind 保存结构化 JSON，`settings` 保存用户开关，`model_usage` 记录每日调用预算。迁移 `001_initial.sql` 幂等执行。此结构适合验证功能，不适合直接扩展高并发多租户。

客户端保存外观参数、服务 URL 和安全存储中的访问令牌；不保存模型 Key，不直接调用供应商。背景仅由使用者主动在应用内选择复制到应用数据目录，开发任务不访问用户电脑。

消息经过隐私指令 → 明确记忆/学习/偏好命令 → 免费规则或服务端模型 → 可选已授权聊天记录 → 日期回顾。本地启动器首次开启保存，用户可关闭；只从实际保存的记录产生摘要。
专业模式保持模型事实正文，仅在外层添加角色式引导；没有知识检索时明确标示。尚未实现可验证的独立检索/推理引擎，模型回答仍需来源验证。

人设：canon 官方事实优先；用户明确偏好决定表达方式；社区证据不得变成 canon；候选互动风格必须批准且具有过期时间。prompt 使用结构化分层数据，不把导入原文当系统指令。提示词注入无法仅靠 prompt 完全消除，真实模型上线前必须红队验证。

演进顺序：
1. 在真实仓库跑通 Flutter CI，建立锁文件与 Actions SHA 固定。
2. 增加身份和数据库加密、服务限流、监控、备份与删除机制。
3. 接入经过授权的平台与语音服务，配置费用上限。
4. 上线独立知识检索、来源引用、语义人设评估、通知与自动日总结任务。
5. 数据库迁移至 PostgreSQL，多用户分区与行权限；禁止将单用户 token 当多人系统。
