# 后续怎么操作

## 1. 把项目接入 GitHub（全程云端）

GitHub 已连接，目标仓库为 Astra-Logiphos/Xavier；先查看项目草稿 PR 和 Actions，检查后合并到 main。无需重新上传源码包。如需手动迁移，可打开 GitHub Codespaces / 云端开发环境。若仓库已有文件，先解压到临时目录，检查 AGENTS.md 与已有目录，再逐文件合并；不要用覆盖解压删除原内容。
完成合并后在云端终端运行：

```bash
python -m unittest discover -s tests -v
python scripts/configure_repo.py 你的GitHub用户名/你的仓库名
git status --short
```

检查只含代码、模板、合成样例与文档，再通过 GitHub 云端编辑器或正常 git 提交推送。不加入 runtime、.env、密钥、数据库、聊天或源码包 ZIP。可先用 PR 合并，保留原工作流。
根目录 README 下载按钮必须替换真实仓库名；脚本只替换占位，不要求任何账号登录。

## 2. 先运行无需模型 Key 的模式

在支持 Python/Docker 和持久卷的云端后端部署项目。照 deployment.md 配 AUTH_TOKEN、HTTPS、数据库路径。ACTIVE_PROVIDER=mock 保持默认。你无需 DeepSeek/智谱 Key，也不会调用收费模型。
规则模式能回应和管理记录，但不能回答所有技术问题；这是成本可控的基础，不是通用免费智能模型。不要在免费模式开启 ALLOW_PAID_API。

## 3. 获得 Android / Windows 应用

仓库 Settings → Actions 确认允许工作流。配置 Android 四个签名 Secrets。打开 Actions → Test，确认通过。再 Run workflow 执行 Build Android、Build Windows，检查 artifacts。
首次应先在测试设备检查 UI、权限、背景、网络、导出和删除。源码包还没有通过此步骤。
两端验证通过后在云端 git 中创建与推送标签：

```bash
git tag v0.1.0
git push origin v0.1.0
```

Actions → Release 成功后，仓库主页 → Releases → Latest：
- Android 下载 xinghui-android.apk；安装需用户主动允许对应来源。AAB 供商店分发，不能直接安装。
- Windows 下载 xinghui-windows.zip，完整解压，运行 xinghui_companion.exe。便携 ZIP 不是签名安装包。
- SHA256SUMS.txt 提供文件校验。没有 Release 成功状态就不能把工作流配置当可下载应用。

## 4. 应用第一次连接

设置 → HTTPS 云端后端地址 → 应用访问令牌（AUTH_TOKEN）→ 保存并连接。不要输入 DeepSeek/智谱 Key。今日页显示版本、打卡和摘要；状态显示 mock_only 等真实能力。
云端部署者配置 ACTIVE_PROVIDER 后，客户端显示当前供应商；客户端不能远程更改费用开关。模型切换在部署平台操作、重启后端。

## 5. 换背景与 UI

外观 → 点星夜/月光/暖春 → 选择背景图片 → 在系统文件选择器主动选自己的授权图片 → 调整遮罩、圆角、字号。
图片 ≤10 MB，支持 PNG/JPEG/WebP；不上传云端。移除背景删除应用副本，不删除用户原文件。
导出主题参数生成 appearance.json；“编辑主题参数”可修改设置。现在能换主题和参数，未来可在该入口增加背景库与气泡皮肤，不是已经支持任意 UI 编辑。

## 6. 人设、来源与审核

来源 → 导入来源：粘贴 URL/必要授权文字、标题、作者、发布时间、平台。URL 不自动爬取。先核对来源，在来源卡片标记官方/粉丝观点/不可靠，官方需版本。
审核中心 → 批准来源 → 添加有来源特征 → 使用该来源 ID，选择 canon_persona 或 community_evidence → 再批准特征。
“我希望你更主动”可在聊天中直接输入，生成偏好候选。去审核中心批准，才能生效。暂停/编辑/删除在特征管理；历史与回滚在版本历史。编辑后需重新批准。
可查看证据、静态预览、JSON/Markdown 导出与回归报告；静态示例不是大模型实际回复。无法自动解决的冲突由你核对。

## 7. 记忆、学习、每日回顾

记忆 → 添加/编辑/删除；“记住这件事：喜欢星空”显式保存。“这句话不要记住”不会保存该轮。
聊天勾选“同意保存学习记录”后发送“今天学了深度学习”，在学习页面填写具体知识点、掌握/未掌握、错题、自己的理解；复习与自测只基于已保存知识点。
今日 → 学习/情绪/陪伴打卡；自定义/补卡填写日期；连续天数由已打卡日期计算。提醒开关只保存偏好，还不会发系统通知。
设置的“保存聊天”默认关闭。你主动开启后，非敏感且允许保存的记录才出现在日期回顾。未保存内容无法自动回忆。

## 8. 语音与更智能的回复

当前语音是模拟，点击不会录音或播放音频。需要部署者以后实现真实 STT/TTS、接入服务端 Key，再完善客户端录音与音频播放。
要真实模型：你自己在供应商平台申请服务端 API Key，把 Key 和当前可用模型名注入部署平台 Secret；API_ENABLED=true、ALLOW_PAID_API=true 可能收费，务必先设置供应商预算。REQUIRE_API_CONFIRMATION 保持 true。
目前没有保证免费的真实云端模型接入；不要让程序凭模型名猜免费，也不要把本地电脑暴露公网给云端 Codex。

## 9. 导出与删除

设置 → 导出个人数据，用户自行选择保存位置；导出文件含私密信息，不上传 GitHub。
删除全部个人数据 → 阅读确认 → 清空当前云端数据库。云备份、平台日志、用户导出需要你额外删除。外观/访问令牌保存在设备，清理应用数据可移除；全量服务端删除不删除用户原背景图片。

## Android 免配置预览与持续改进

到 Releases 下载 xinghui-android-preview.apk，主动允许安装来源，打开 → 聊天；外观 → 主题/背景/字号。未连接后端时是规则预览，临时聊天不保存，不具备通用推理。
要长期相处学习，先连接云端后端，设置开启保存聊天 → 学习规则启用相处记忆 → 自然聊天 → 审核候选点“记住”。详见 evolution-rules.md。官方人设不因聊天自动修改。
