# 相处中的学习、推理与记忆

目标不是偷偷修改角色或模型权重，而是建立有证据、能审核、能撤销的个性化循环：
已同意保存的对话 → 保守提取候选 → 解释来源与理由 → 用户确认 → 个人记忆/短期互动偏好 → 相关性检索 → 改善回复 → 继续反馈。

## 三个独立规则

| 规则 | 默认 | 做什么 | 不做什么 |
|---|---|---|---|
| 搜寻人设资料 | 关闭 | 配置关键词、排除词与平台，创建待处理搜寻任务 | 未授权连接器不执行真实外部搜索；搜索不能直接修改 canon |
| 自行添加 | 开启 | 手动来源导入与显式 user_preference | 不将粉丝观点冒充官方 |
| 相处记忆 | 关闭 | 分析已同意保存的非敏感对话，提出记忆候选 | 未确认不参加长期检索；不改官方剧情 |

在客户端“学习规则”逐个开关，互不强制依赖。搜寻规则当前只排队，status=awaiting_connector_authorization，不能把任务创建当搜索成功。手动规则指引跳转到来源页，原有显式添加可独立使用。

## 如何让它逐渐懂你

1. 先连接云端后端（预览 APK 没有自动部署后端）。
2. 设置 → 明确开启“保存聊天”；再学习规则 → 启用“从相处中提出记忆候选”。两者必须同时同意。
3. 自然对话如“我喜欢星空”“我最近在学习深度学习”“我通常晚上复习”。当前保守规则提取 profile / learning / relationship 候选。
4. 学习规则 → 审核相处记忆候选，查看原始必要摘录、触发轮次、理由、0.6 初始置信度、30 天到期。
5. 点“记住”才变成 approved 个人记忆。人确认后 confidence=1.0 代表“你确认这条记录”，extracted_confidence=0.6 仍保留机器提取的不确定性。
6. 后续“你记得我喜欢什么吗”只检索已确认、同意且未删除的个人记忆。删除记忆时关联候选也删除，避免从候选复活。
7. 如果偏好改变，修改/删除记忆；角色表达调整用人设审核中心的 user_preference。个人事实与角色事实分开。

“不要记住/不要记录”与 no_save 优先；此轮不保留或产生候选。敏感规则会过滤候选，但启发式不是全覆盖检测，不能用它代替隐私控制。

## 短期互动风格

目前只有少量明确反馈规则。例如“这样温柔的语气让我安心”在至少 3 个已同意保存的轮次、至少 2 个本地日期出现，才能生成 interaction_style 候选。
记录 supporting_turn_ids、trigger_turn_id、confidence=0.7、scope、expires_at；你在人设审核中心批准后生效，过期会移出有效人设。这不是自动推断永久性格。
官方 canon 永远由人工来源审核更新；相处记忆永不覆盖剧情。

## 当前推理能力与下一步

已实现的是确定性提取与中文双字/英文词的检索，不是已经训练出通用模型推理。真实 DeepSeek/智谱配置后，相关已确认记忆随服务端提示输入模型。角色语气与专业事实分开处理。
下一步可替换为 LLM 结构化提取、语义检索、矛盾检测、近期/长期记忆权重、回顾纠错与安全评测，但所有自动结果仍留在候选队列，不因模型输出就当事实，不用聊天天然授权敏感记忆。
权重微调、全自动自我学习和真实模型语义回归未实现。费用仍需部署者管理。

## API

- GET /rules；PATCH /rules/{rule_id}：enabled/keywords/exclude_keywords/platforms，不能关闭审核门禁。
- POST /rules/persona_search/run：创建真实标示未执行的搜寻任务。
- GET /memory-candidates：查看候选。
- POST /memory-candidates/review：id + action=approve/reject/defer。

关闭规则停止以后提取，不删除既有记录；彻底删除通过记忆管理/全量数据删除。过期候选不能批准。

相反偏好如“我喜欢星空”与“我不喜欢星空”会标记与已有已确认记忆的冲突。请先在记忆管理中核对、修改或删除旧记录；系统不会强行合并。此检测是保守文本规则，非完整语义矛盾检测。
